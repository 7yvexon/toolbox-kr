# HWP conversion architecture

## 결론

현재 정적 웹 애플리케이션에는 `HWP ↔ PDF`를 가장한 불완전한 변환기를 포함하지 않습니다.

- 한컴 공식 통합문서뷰어는 `HWP/HWPX → PDF`의 `doc2pdf` 변환을 지원합니다.
- 해당 API는 통합문서뷰어가 정상 설치된 서버를 전제로 하는 REST API입니다.
- 공식 변환표에서 PDF 입력은 JPG, PNG, TEXT 출력만 지원하며 `PDF → HWP/HWPX`는 지원하지 않습니다.
- HWPX는 개방형 XML 패키지이지만 직접 렌더러를 구현해 한글과 동일한 페이지 나눔, 글꼴, 표, 수식과 개체 배치를 재현하는 것은 별도의 문서 엔진 프로젝트입니다.

공식 참고 자료:

- [한컴 통합문서뷰어 개요](https://developer.hancom.com/docsconverter/overview)
- [공식 변환 쌍과 API](https://developer.hancom.com/docsconverter/guide/api/module)
- [한글 SDK](https://www.hancom.com/product/sdk/hwpSdk)
- [HWPX 포맷 구조](https://tech.hancom.com/hwpxformat/)

## 목표 구조

```text
Browser
  ├─ 기존 이미지·PDF 도구: 브라우저 안에서 처리
  └─ HWP → PDF: 명시적 업로드 동의
       ↓ HTTPS
Conversion API
  ├─ 인증·속도 제한·크기 제한
  ├─ 악성 파일 검사
  ├─ 작업별 격리 디렉터리
  └─ 라이선스가 적용된 한컴 변환 엔진
       ↓
짧은 만료 시간의 결과 다운로드 → 즉시 삭제
```

## 출시 전 필수 조건

1. 한컴 SDK 또는 통합문서뷰어의 서비스 제공 라이선스를 서면으로 확인합니다.
2. 변환 서버와 웹 앱을 분리하고 API 키·라이선스 파일을 브라우저 번들에 포함하지 않습니다.
3. 업로드 전에 서버 처리, 보관 시간과 삭제 정책을 명확히 고지하고 동의를 받습니다.
4. HWP/HWPX 파일의 크기, 실제 시그니처, 암호·DRM 여부와 악성 코드 검사를 적용합니다.
5. 변환 작업은 사용자별·작업별로 격리하고 CPU, 메모리와 처리 시간을 제한합니다.
6. 원본과 결과 파일은 암호화된 임시 저장소에서 최소 시간만 보관한 뒤 삭제합니다.
7. 로그에는 파일 내용, 원본 파일명, 문서 제목과 사용자 개인정보를 기록하지 않습니다.
8. 표, 글꼴, 각주, 수식, 차트, 배포용 문서와 암호 문서를 포함한 회귀 샘플로 시각 검수합니다.

## PDF → HWP 정책

공식 변환 엔진이 지원하지 않는 `PDF → HWP/HWPX`를 정확한 문서 복원으로 광고하지 않습니다. 향후 OCR과 레이아웃 분석을 이용한 기능을 검토하더라도 다음과 같이 별도 제품으로 표시해야 합니다.

- 결과 형식은 레거시 HWP가 아닌 HWPX 우선
- “원본 복원”이 아니라 “편집 가능한 초안 생성”으로 고지
- 표, 수식, 다단 편집, 글꼴과 페이지 나눔의 손실 가능성을 변환 전에 표시
- 원본 PDF와 결과 HWPX의 자동·수동 시각 비교 절차 제공
