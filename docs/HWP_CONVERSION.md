# HWP 변환 아키텍처

## 현재 구현

`HWP 5.0/HWPX → PDF`는 브라우저에서만 실행되는 베타 기능입니다.

```text
사용자 파일 선택
  → 확장자·MIME·파일 시그니처·20MB 제한 확인
  → @rhwp/core WebAssembly 지연 로딩
  → 최대 50페이지 확인
  → 페이지별 Canvas 렌더링
  → pdf-lib로 이미지형 PDF 생성
  → 브라우저 다운로드
```

- HWP/HWPX 원본과 결과는 서버로 전송하지 않습니다.
- WASM 엔진은 `/hwp-to-pdf`에 진입한 뒤 파일을 선택할 때만 불러옵니다.
- 페이지를 순차 처리하고 전체 렌더 픽셀 수를 제한해 메모리 사용을 제어합니다.
- 렌더링된 SVG를 DOM에 삽입하지 않고 Canvas로 직접 그려 문서가 HTML이나 스크립트를 실행할 경로를 만들지 않습니다.
- 암호·DRM·배포용 보호 문서와 손상된 문서는 지원 대상이 아닙니다.

## 결과물 특성

PDF는 각 HWP 페이지를 고화질 이미지로 렌더링해 생성합니다. 화면 배치를 보존하기 쉬운 대신 텍스트 검색·선택, 링크, 접근성 태그는 보존되지 않습니다. 원본 글꼴이 사용자 기기에 없거나 오픈소스 엔진이 아직 지원하지 않는 개체가 있으면 배치 차이가 날 수 있습니다.

따라서 화면에 다음 내용을 명시합니다.

1. 베타 기능임을 표시합니다.
2. 복잡한 표·수식·글꼴은 원본과 다를 수 있음을 알립니다.
3. 결과 PDF와 원본을 반드시 비교하도록 안내합니다.
4. 서버 전송이 없다는 사실과 이미지형 PDF라는 한계를 함께 표시합니다.

## 적용한 제한

| 항목 | 제한 |
| --- | --- |
| 파일 크기 | 20MB |
| 페이지 수 | 50페이지 |
| 전체 렌더 픽셀 | 1억 4천만 픽셀 |
| 지원 입력 | OLE 기반 HWP 5.0, ZIP 기반 HWPX |
| 지원하지 않는 입력 | 암호·DRM·배포용 보호 문서, HWP 3.x, 손상 문서 |

확장자만 신뢰하지 않습니다. `.hwp`는 OLE Compound File 시그니처, `.hwpx`는 ZIP 시그니처와 일치해야 하며 이후 WASM 파서가 실제 문서 구조를 검증합니다.

## 엔진과 라이선스

- 현재 엔진: `@rhwp/core` 0.8.x
- 라이선스: MIT
- 상태: 0.x 베타
- 관계: 한글과컴퓨터와 제휴·후원·승인 관계가 없는 독립 오픈소스 프로젝트

의존성 버전은 lockfile에 고정하고, CI에서 테스트·프로덕션 빌드·`npm audit --audit-level=high`를 실행합니다.

## 정확도 우선 확장 경로

한컴 공식 통합문서뷰어 또는 HWP SDK를 도입하면 서버 변환을 별도 선택지로 추가할 수 있습니다. 이 경우 현재의 “서버 전송 없음” 모델과 분리하고 다음 조건을 모두 충족해야 합니다.

1. 상용 서비스 사용이 가능한 서면 라이선스를 확인합니다.
2. 업로드 전 서버 처리·보관 시간·삭제 정책에 별도 동의를 받습니다.
3. 변환 API에 인증, 속도·크기 제한, 악성 파일 검사와 작업별 격리를 적용합니다.
4. 원본과 결과는 암호화된 임시 저장소에서 최소 시간만 보관한 뒤 삭제합니다.
5. 파일 내용, 원본 파일명, 문서 제목과 개인정보를 로그에 남기지 않습니다.
6. 문서 회귀 테스트로 글꼴, 각주, 표, 수식, 차트와 배포용 문서를 확인합니다.
